# Vector Barrage

A fixed-shooter arcade game built with **Python 3.13** and **Pygame 2.6.1**.

Vector Barrage is presented as a **source-first portfolio repository**. The public repository is intended to demonstrate software architecture, deterministic gameplay rules, persistence, automated testing, engineering documentation and reproducible execution from source.

> **Publication profile:** source code and engineering evidence are public; a compiled `VectorBarrage.exe` is **not** distributed under the current profile.

## Features

- Spanish-language menu and user interface.
- Iterative, non-recursive screen/navigation coordinator.
- Horizontal player movement with bounded positioning.
- Player firing and deterministic enemy progression.
- Collision handling with exactly-once enemy removal, scoring and destruction audio.
- Score, lives, level progression and Game Over flow.
- Strict new-record rule: a score must be greater than the previous maximum.
- UTF-8 score persistence with malformed-line tolerance and descending Top 5 display.
- Canonical `scores.txt` storage with first-run initialization and legacy migration behavior.
- Procedural visual presentation using Pygame drawing primitives.
- Procedural PCM audio generated by the application.
- Host-system font resolution; no bundled gameplay font file is required.
- Automated regression coverage across gameplay rules, storage, navigation, media boundaries, fonts and packaging contracts.

## Quick Start

### 1. Clone and enter the repository

```bash
git clone https://github.com/VictorDector/vector-barrage-python-pygame.git
cd vector-barrage-python-pygame
```

### 2. Create a virtual environment

Linux / macOS:

```bash
python3.13 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Install the project

```bash
python -m pip install --upgrade pip
python -m pip install -e .
```

For development and tests:

```bash
python -m pip install -e ".[dev]"
```

### 4. Run Vector Barrage

```bash
python -m vector_barrage
```

## Architecture

The public implementation is organized as a Python package:

```text
src/vector_barrage/
├── __init__.py
├── __main__.py
├── app.py
├── config.py
├── resources.py
├── storage.py
├── audio.py
├── links.py
├── ui_fonts.py
├── gameplay/
│   ├── __init__.py
│   ├── model.py
│   ├── rules.py
│   ├── session.py
│   └── renderer.py
└── screens/
    ├── __init__.py
    ├── menu.py
    ├── scores.py
    ├── about.py
    └── name_entry.py
```

Key boundaries:

- `app.py` coordinates screen state and application flow.
- `gameplay/` separates deterministic rules/model behavior from the Pygame runtime session and renderer.
- `storage.py` owns canonical score parsing, initialization, migration and persistence.
- `audio.py` owns procedural sound generation and injectable audio behavior.
- `resources.py` separates source-mode and frozen read-only resource locations.
- `ui_fonts.py` resolves approved host-system fonts without relying on Pygame's bundled default font asset.
- `screens/` owns individual UI screens and input handling.

See `02_architecture/` and `04_solution/` for the detailed engineering dossier.

## Windows Packaging Engineering Evidence

The repository retains a controlled PyInstaller specification and hook configuration under `packaging/`. A hardened Windows executable was built and subjected to archive, runtime, first-run initialization and persistence/relaunch QA.

That work demonstrates packaging capability, but **the compiled executable is not published or attached as a GitHub Release asset under the current portfolio profile**. If binary distribution is introduced in the future, its binary-specific third-party compliance gate must be reopened.
