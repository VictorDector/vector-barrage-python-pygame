## Purpose

Define the visual/audio media boundary of Vector Barrage and the publication implications of its generated-media design.

## Decision

Vector Barrage `v1.1.0` uses fully programmatic visual presentation and procedurally synthesized audio. No external gameplay image, sprite, logo, music or sound-effect file is required by the current candidate.

This is the intended product design, not a placeholder strategy.

## Visual Media

Renderer/screens generate presentation at runtime using Pygame drawing primitives and text rendered through an approved **host-system font** resolved by `ui_fonts.py`.

| Element | Current implementation | External binary media |
|---|---|---|
| Main Menu/background | Generated fills/grid/text/selection state | None |
| Gameplay background | Generated presentation | None |
| Player | Generated geometry | None |
| Enemies | Generated geometry/accents | None |
| Projectiles | Generated geometry | None |
| HUD | Host-font runtime text | None |
| Game Over | Generated overlay/text | None |
| Scores | Generated UI/text | None |
| About | Generated UI/text | None |
| Name Entry | Generated UI/text | None |

No copied font file is stored in the repository or required by the current UI design.

## Audio Media

`src/vector_barrage/audio.py` synthesizes signed 16-bit PCM from numeric tone definitions.

| Cue | Behavior |
|---|---|
| Menu | Looping procedural tone pattern |
| Gameplay | Looping procedural tone pattern |
| Enemy destroyed | Short procedural one-shot |
| New record | Short procedural success sequence |

`ProceduralAudioService` is the normal runtime implementation. Mixer/device failures fail soft. `NullAudioService` remains a separate injectable no-op implementation for tests or deliberately audio-disabled contexts.

## Audio Ownership

```text
MENU
-> play_menu_music()
-> stop before leaving menu

GAME
-> play_gameplay_music()
-> enemy destroyed -> play_enemy_destroyed()
-> stop before leaving gameplay

STRICT NEW RECORD
-> play_new_record()
-> stop after name-entry flow
```

This keeps audio semantic rather than coupled to external filenames.

## Public Rights / Provenance Boundary

```text
external gameplay artwork        = NONE
external gameplay audio          = NONE
copied font file                  = NONE
visual presentation              = GENERATED BY PROJECT SOURCE + HOST FONT
```

Third-party software libraries retain their own licenses. The generated-media design does not relicense Python, Pygame or build tooling.

## Packaging Implication

The controlled PyInstaller configuration does not require gameplay image/audio directories because none exist in the current design. The accepted hardened package demonstrated that generated media and host-font rendering work in packaged execution.

Packaging material is retained as engineering evidence; the executable itself is not distributed under the current source-first profile.

## Future Media Change Rule

Any new external media file requires, before public use:

1. source/provenance identification;
2. authorship/license/redistribution disposition;
3. stable repository path;
4. runtime resource-resolution update;
5. automated/target runtime regression where relevant;
6. packaging inclusion update where applicable;
7. fresh evidence if appearance/audio changes materially.
